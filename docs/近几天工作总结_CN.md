## 3. 前端 RTL 与结构层工作

### 3.1 四种数据流的正式入口完成统一

当前仓库里更适合作为正式前端实现入口来评审的，不再是历史遗留的底层 mesh 顶层，而是四个标准包装层：

- `ws/src/standard_ws_array_4x4.v`
- `is/src/standard_is_array_4x4.v`
- `os/src/standard_os_array_4x4.v`
- `dip/src/standard_dip_array_4x4.v`

这样做的价值是：

- 对外接口统一为标准 GEMM 风格接口。
- `.txt` 文件驱动回归可以统一复用。
- 后续综合、后仿、形式验证、ICC2、Calibre 的承接对象明确。

### 3.2 四种数据流语义重新梳理并落回到实现口径

最近几天对四种数据流的理解和评审口径做了重新收敛：

- `WS`：权重尽量驻留在 PE，输入与部分和流动。
- `IS`：输入尽量驻留在 PE，权重流动，部分和继续传播。
- `OS`：输出/部分和驻留在 PE，本地累加后统一读出。
- `DiP`：输入按对角方向传播，权重采用旋转布局，输出序列需要按完整结果流来验证。

对应地，仓库中的评审重点也从“某个内部阵列会不会动”转成了“对外黑盒接口是否真正体现了数据流语义”。

### 3.3 `DiP` 的面向边缘计算 RTL 优化继续推进

这几天 `DiP` 继续向“低无效翻转、低控制开销”的方向优化，比较明确的三点是：

1. `dip/src/dip_pe.v`
   - 引入 `stage1_mac_en`。
   - 把“这一拍是否真的需要做 MAC”的判断前移到 `stage1` 并寄存。
   - `stage2` 只有在 `valid` 且确有贡献时才让乘加路径真正切换。

2. `dip/src/standard_dip_array_4x4.v`
   - 在 `input_row_valid=0` 的周期不再每拍重写 `stream_input_row_data`。
   - 对空拍输入做总线保持，减少无效输入切换向内核传播。
   - 输入结束后自动补一拍 `drain`，确保最后结果由 RTL 本身冲出，而不是靠 testbench 取巧。

3. `dip/src/systolic_array_dip_4x4.v`
   - 只有真正采集到底部有效结果行时才更新 `output_row_data_reg`。
   - 无新结果时保持输出寄存稳定，避免输出总线在空拍抖动。

这些优化的共同目标是：

- 不破坏 `DiP` 的数据流语义。
- 保持可综合和可验证。
- 为边缘计算场景下的功耗/翻转优化提供更可信的前端基础。

## 4. 统一验证与回归机制建设

### 4.1 `.txt` 文件驱动回归成为统一主口径

当前项目已经不再依赖单个 testbench 自己“硬编码一组激励就算验证完成”的方式，而是统一采用：

- `.txt` 输入矩阵
- `.txt` 标准输出矩阵
- 自动比对结果

这样做的好处是：

- 四种数据流使用同一批测试向量，便于公平比较。
- 结果更容易沉淀为论文和报告中的统一口径。
- 后续无论使用 `iverilog` 还是 `VCS`，都可以复用同一套用例。

### 4.2 当前统一回归结果

根据 `docs/边缘优化实践与实现说明_CN.md`，在 `iverilog` 下四架构统一 `.txt` 回归结果为：

| 架构 | 结果 |
|---|---|
| `WS` | `268/268 PASS` |
| `IS` | `268/268 PASS` |
| `OS` | `268/268 PASS` |
| `DIP` | `268/268 PASS` |
| 总计 | `1072/1072 PASS` |

这意味着：

- 四种数据流在统一文件向量口径下都已经可稳定回归。
- 目前可以把“前端功能正确性”作为较稳妥的结论写入阶段性总结。

### 4.3 `.txt` 回归驱动增强为 soft-fail 模式

最近几天 `utils/run_file_vector_suite.py` 和四个 file testbench 做了一个很实用的增强：

- 编译失败仍然立即停。
- 单个 case 仿真失败、超时或 mismatch 时，不再整套向量立即终止。
- 整个回归会继续跑完整套向量，最后统一统计 `pass/fail`。

这个改动的价值非常实际：

- 更适合故意注错后观察失败分布。
- 更适合快速评估某次 RTL 改动是“个别 case 出问题”还是“整套行为塌掉”。

## 5. `DiP` 的稀疏/跳过数据（非覆盖率）

虽然本文档不讨论功能覆盖率，但 `.txt` 回归中已经积累了 `DiP` 在稀疏场景下很有价值的一组统计量。

`dip/sim/txt_vectors/iverilog/summary.log` 的汇总结果为：

| 指标 | 数值 |
|---|---|
| `cases` | `268` |
| `active_mac` | `8162` |
| `total_mac` | `17152` |
| `zero_gated` | `8990` |
| `avg_skip_pct` | `52.41%` |

可以从这组数据读出几个结论：

1. 当前测试向量集中，`DiP` 平均有超过一半的潜在 MAC 被 zero-gating 跳过。
2. 这说明目前的 `DiP` 优化并不是空喊“低功耗”，而是已经能在前端行为层体现出明显的跳过收益。
3. 对边缘计算主题来说，这组数据比单纯说“功能过了”更有论文价值。

另外，日志里还可以看到两个极端 case：

- `wide_range`：`active_mac=64/64`，`skip_ratio=0.0%`
- `zero_input`：`active_mac=0/64`，`skip_ratio=100.0%`

这说明当前统计逻辑本身是有分辨力的，能够区分完全稠密和极端稀疏输入。
