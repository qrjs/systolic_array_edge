# 论文大纲（面向边缘计算的脉动阵列）

## 一句话主线

这篇论文最适合收敛成一条很清楚的主线：

- 在统一平台上实现并比较 `WS / IS / OS / DiP`
- 以 `DiP` 为核心对象进行面向边缘计算的 RTL 优化
- 用统一前端验证和后端评估说明“改进型 `DiP` 更适合作为边缘场景候选数据流”

一句话再压缩就是：

`WS / IS / OS` 用来建立基线，`DiP` 用来承载你的主要贡献。

---

## 为什么要优化现在的结构

你原来的大纲信息很全，但容易出现三个问题：

1. `WS / IS / OS / DiP` 写得过于平权，主角不够突出
2. “理论基础”“统一平台”“DiP 优化”“验证流程”拆得太散，章节之间容易重复
3. 容易写成项目记录，而不是围绕一个核心结论逐层论证的论文

所以更好的做法不是再加内容，而是收束成：

- 一个核心问题
- 一条证据链
- 六章以内讲清楚

---

## 推荐题目

优先推荐下面这种写法：

1. 面向边缘计算的脉动阵列数据流比较与优化设计：以改进型 DiP 为中心
2. 面向边缘计算的多数据流脉动阵列设计与评估：WS、IS、OS 对比及改进型 DiP 实现
3. 面向边缘计算的脉动阵列数据流优化研究：统一比较平台与改进型 DiP 设计

如果老师更保守，可以用：

4. 面向边缘计算的脉动阵列 RTL 设计与验证研究

不建议再把题目写成“DiP 复现”，因为你现在的工作已经明显超过“复现”。

---

## 论文最该回答的 3 个问题

绪论里建议只保留这 3 个核心问题，不要铺太多：

1. 在统一实现与统一验证口径下，`WS / IS / OS / DiP` 各自有什么结构与部署特点？
2. 原始 `DiP` 在边缘计算场景下存在哪些实现层问题，为什么值得优化？
3. 改进型 `DiP` 是否能在保证功能正确的前提下，在面积、时序、功耗或能效指标上体现出更好的边缘适配性？

这样后面的每一章都很好落：

- 第 2、3 章回答“是什么”和“怎么做”
- 第 4 章回答“有没有做对”
- 第 5 章回答“值不值得”

---

## 建议改成 6 章结构

相比 7 章结构，我更建议你用 6 章：

1. 绪论
2. 相关基础与统一比较口径
3. 统一架构实现与改进型 DiP 设计
4. 前端验证方法与结果分析
5. 后端评估与边缘适配性分析
6. 结论与展望

这样更紧，也更像一篇围绕“一个主问题”的本科论文。

---

## 第 1 章 绪论

这一章只做 6 件事：

1. 研究背景
   边缘计算设备受限于功耗、面积、带宽和实时性，数据流选择直接影响脉动阵列的实现质量。

2. 研究意义
   不能只比较“能不能算”，还要比较“后端是否更容易落地”。

3. 研究现状
   简述 `WS / IS / OS` 是经典数据流，`DiP` 代表新的传播方式，但工程化比较与边缘导向优化还不充分。

4. 研究问题
   直接写上面那 3 个核心问题。

5. 研究内容与技术路线
   用一张流程图串起来：
   `统一平台 -> 基线实现 -> DiP 优化 -> 前端验证 -> 后端评估 -> 结论`

6. 论文贡献
   本科论文不要写得太夸张，建议写成“主要工作与贡献”。

这一章最重要的任务不是堆概念，而是告诉读者：

- 这不是“四种数据流平均介绍”
- 而是“以改进型 `DiP` 为中心的比较与优化研究”

---

## 第 2 章 相关基础与统一比较口径

这一章建议把原来“理论基础”和“公平比较前提”合并，避免后面重复。

可以写 5 节：

1. 脉动阵列基本原理
   说明 MAC 阵列、数据流动、局部复用和矩阵乘法映射关系。

2. `WS / IS / OS / DiP` 的结构语义
   每种数据流只讲最核心的传播特征，不要在这里放太多实现细节。

3. 边缘计算关注的硬件指标
   包括面积、时序、功耗、访存压力、无效翻转和能效。

4. 统一比较口径
   说明为什么必须统一：
   - 位宽
   - 阵列规模
   - 输入输出接口
   - 测试向量
   - 统计指标

5. 本章小结
   收束成一句话：
   边缘场景下，数据流优劣必须在统一实现和统一评估口径下讨论。

这一章的作用是给后文搭“裁判规则”，而不是开始展示你的实现细节。

---

## 第 3 章 统一架构实现与改进型 DiP 设计

这是全篇最重要的一章，建议篇幅最长。

这一章不要把 `WS / IS / OS` 和 `DiP` 完全平铺。
更好的组织方式是：

1. 统一工程框架与设计原则
   说明四种数据流都采用统一 top 级接口和统一验证入口。

2. 三种基线数据流实现
   对 `WS / IS / OS` 只写成一组基线：
   - 结构语义
   - RTL 实现要点
   - 各自的预期特点

3. 原始 `DiP` 结构与问题分析
   这是从“基线组”切到“主角组”的关键转折。
   要讲清楚原始 `DiP` 在边缘场景下的问题，例如：
   - 无效翻转
   - 控制路径偏重
   - 输出采集和边界时序压力
   - 后端实现负担

4. 改进型 `DiP` 设计目标
   建议明确写成：
   - 保持数据流语义不变
   - 保持统一接口不变
   - 优先减少无效活动
   - 改善实现质量

5. 改进型 `DiP` 的 RTL 优化策略
   这里集中展开你的真正贡献：
   - `zero-gating`
   - `valid-gating`
   - 无效周期寄存保持
   - 输出收集寄存化
   - 控制路径整理

6. 改进前后对比总结
   建议放一张表：
   - 原始问题
   - 对应优化
   - 预期收益

这一章结束后，读者应该已经明白两件事：

1. 你不是只“实现了四种数据流”
2. 你真正做的是“在统一平台上把 `DiP` 朝边缘友好方向推进了一步”

## 第 4 章 前端验证方法与结果分析

这一章的目标只有一句话：

先证明你的优化没有把功能做坏。

建议按下面的顺序写：

1. 验证目标与验证原则
   强调正式验证统一采用“文本输入 + 文本标准答案 + 自动比对”的口径。

2. 验证平台与 testbench 组织
   这里可以自然解释：
   - 为什么要用统一 `.txt` 向量
   - 为什么保留 `run / wave` 作为调试验证
   - `.svh` 只是公共任务封装，不是另一套验证逻辑

3. 固定基准回归结果
   展示 `WS / IS / OS / DiP` 的统一通过结果。

4. 随机场景补充验证
   用 `random` 回归说明不是只在少量固定样例上成立。

5. 波形与关键行为分析
   只选最有代表性的图，不要每种数据流都铺很多波形。

6. 稀疏场景与 zero-gating 分析
   把这一节作为从“功能正确”过渡到“边缘友好”的桥。

7. 本章小结
   结论要明确：
   改进型 `DiP` 在统一前端口径下保持了功能正确性，并体现出减少无效活动的潜力。

这一章建议避免两个问题：

- 不要把太多 Makefile 细节写进正文
- 不要把验证日志原样搬进去

正文只放“方法、代表性结果、结论”，详细日志放附录。

## 第 5 章 后端评估与边缘适配性分析

这一章回答最终问题：

为什么改进型 `DiP` 更适合边缘计算。

建议写 6 节：

1. 评估目标与统一约束
   说明工艺、时钟约束、综合配置、top 选择和指标定义。

2. FPGA 评估结果
   可以先写你当前已经比较容易拿到的资源、时序和功耗。

3. ASIC 流程与评估计划
   即使数据还没完全补齐，也可以先把方法交代清楚。

4. 四种数据流的结果对比
   这一节的主角仍然是“改进型 `DiP` 相对基线组”的表现。

5. 边缘适配性讨论
   从下面几个角度展开：
   - 面积压力
   - 时序收敛难度
   - 动态功耗来源
   - 无效翻转控制
   - 综合平衡性

6. 本章小结
   收束成一句明确结论，不要只罗列表格。

这一章最忌讳的是：

- 表很多，但没有结论
- 每个指标都分析一点，却没有回到“边缘适配性”这个中心词

所以建议你每张表后面都回答一句：

这说明改进型 `DiP` 在边缘场景中的什么优势或代价。

## 第 6 章 结论与展望

这一章不用写长，关键是收得稳。

建议分 4 节：

1. 工作总结
   概括统一平台、基线比较、`DiP` 优化、前后端评估。

2. 主要结论
   建议写成 3 条，不要超过 4 条。

3. 论文贡献归纳
   用“完成了什么”来写，不要用“首次提出”之类过满表述。

4. 不足与后续工作
   可以写：
   - 更大规模阵列
   - 更完整 ASIC 后端闭环
   - 板级验证
   - 更丰富工作负载

## 你这篇论文最适合强调的贡献写法

建议最终写成下面 3 点：

1. 构建了一套面向边缘计算的多数据流脉动阵列统一实现与验证平台
   在统一接口、统一位宽和统一文本向量口径下，实现并比较 `WS / IS / OS / DiP`。

2. 针对 `DiP` 提出并实现了一组面向边缘计算的 RTL 级优化策略
   通过 `zero-gating`、`valid-gating`、寄存保持和控制路径整理，降低无效活动并改善实现质量。

3. 建立了“前端功能正确性 + 后端实现质量”联合评估方法
   不只比较能否正确计算，还比较面积、时序、功耗与边缘适配性。

这 3 点已经足够本科论文使用，不需要再额外堆“创新点”。

## 摘要建议按这个顺序写

摘要推荐 5 句结构：

1. 边缘计算对脉动阵列的数据流选择和硬件实现质量提出了更高要求。
2. 为系统比较不同数据流并探索更适合边缘场景的设计，本文在统一平台上实现了 `WS / IS / OS / DiP` 四类 4x4 脉动阵列。
3. 在此基础上，针对 `DiP` 的实现特点，提出并完成了一组面向边缘计算的 RTL 级优化。
4. 通过统一文本向量驱动的前端验证以及后端评估，证明改进型 `DiP` 在保证功能正确的前提下表现出更好的边缘适配潜力。
5. 研究结果表明，改进型 `DiP` 在面积、时序、功耗与无效活动控制之间取得了更优平衡。
