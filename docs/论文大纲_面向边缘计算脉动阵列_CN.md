# 论文大纲（面向边缘计算的脉动阵列）

## 一句话主线

这篇本科毕业论文最适合写成下面这条主线：

- 先在统一平台上实现并比较 `WS / IS / OS` 三种传统数据流
- 再以 `DiP` 为重点，做面向边缘计算的 RTL 优化
- 最后用统一前端验证结果和后续补齐的后端数据，证明“优化后的 DiP 更适合边缘计算场景下的脉动阵列设计”

换句话说：

- `WS / IS / OS` 是基线
- 原始 `DiP` 是论文来源和改进起点
- 优化后的 `DiP` 才是你的核心贡献对象

---

## 题目建议

优先推荐：

1. 面向边缘计算的脉动阵列数据流优化设计与实现：WS、IS、OS 对比及改进型 DiP 研究
2. 面向边缘计算的脉动阵列数据流比较与优化：以改进型 DiP 为中心的设计与验证
3. 面向边缘计算的多数据流脉动阵列设计与评估：传统数据流对比与 DiP 优化实现

不建议继续使用“DiP 复现”作为题目关键词，因为你的论文重点已经不是单纯复现，而是：

- 在统一平台上比较传统数据流
- 做边缘导向的 DiP 工程优化
- 用后端数据支撑结论

---

## 研究目标与核心问题

建议在绪论里把研究目标收敛成这 4 个问题：

1. 在统一接口、统一位宽、统一验证向量下，`WS / IS / OS` 三种传统数据流各自有什么结构特点和边缘部署代价？
2. 原始 `DiP` 相比传统数据流，在数据传播方式和资源利用方式上有什么潜在优势？
3. 面向边缘计算，能否通过 RTL 级优化进一步降低 `DiP` 的无效翻转、控制开销和实现压力？
4. 在统一后端口径下，优化后的 `DiP` 是否能够在面积、时序、功耗或能效指标上体现出更适合边缘计算的特征？

这样写的好处是：

- 论文主线非常明确
- 每一章都能围绕问题展开
- 后端数据的作用也自然变成“回答第 4 个问题”

---

## 创新点与贡献写法

本科论文这里要避免夸大。最稳妥的写法不是“提出全新数据流”，而是：

1. 构建了一套面向边缘计算的多数据流脉动阵列统一实现与比较平台  
   在统一 RTL 风格、统一测试向量、统一约束与统一指标口径下，对 `WS / IS / OS / DiP` 进行公平对比。

2. 针对 `DiP` 实现了一组面向边缘计算的 RTL 级优化策略  
   包括 `zero-gating`、`valid-gating`、无效周期寄存保持、输出收集寄存化、控制路径轻量化等，目标是减少无效翻转并改善边缘场景下的实现质量。

3. 提出一套“前端正确性 + 后端实现质量”联合评估方法  
   不是只比较功能是否正确，而是继续比较资源、时序、功耗和后端可实现性，让“为什么更适合边缘计算”有工程证据支撑。

4. 以改进型 `DiP` 为中心，给出与 `WS / IS / OS` 的系统化对比结论  
   说明不同数据流的优势不只来自算法语义，也来自实现层面的布线、控制、翻转与时序特征差异。

如果老师希望“创新点”更保守，可以改成“主要工作与贡献”。

## 摘要写作要点

摘要建议按这个顺序写：

1. 背景  
   边缘计算设备受限于功耗、带宽、面积与实时性，对脉动阵列的数据流选择提出更高要求。

2. 问题  
   传统 `WS / IS / OS` 数据流各有优缺点，而 `DiP` 具备新的传播机制，但其工程实现与边缘适配性仍需系统验证。

3. 方法  
   在统一平台上实现 `WS / IS / OS / DiP` 四类 4x4 脉动阵列，重点对 `DiP` 进行面向边缘计算的 RTL 优化，并建立统一前后端评估流程。

4. 结果  
   前端功能验证通过，优化后的 `DiP` 在后端评价指标上相较传统数据流表现出更好的边缘适配潜力。

5. 结论  
   改进型 `DiP` 在资源利用、低翻转设计与后端实现质量之间取得更优平衡，更适合作为面向边缘计算的脉动阵列候选数据流。

### 第 4 章 面向边缘计算的改进型 DiP 设计

这是全篇最核心的一章，建议写得最细。

4. 面向边缘计算的 RTL 优化策略  
   包括 `zero-gating`、`valid-gating`、无效周期寄存保持、边界输出寄存化、控制路径整理
5. 改进前后 `DiP` 的结构差异总结  
6. 本章小结
