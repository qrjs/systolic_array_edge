# 边缘优化实践与实现说明（WS/IS/OS）

本文档说明当前仓库在标准数据流实现基础上，针对边缘计算场景新增的低功耗实现策略，以及对应代码位置与验证方法。

## 1. 优化目标

边缘设备通常受限于功耗与带宽。对脉动阵列来说，常见可优化点是：

- 避免无效 MAC（例如某一操作数为 0）
- 避免无效周期寄存器翻转（valid=0 时仍持续改写数据寄存器）

本次优化遵循“功能不变、实现可综合、验证可复现”的原则。

## 2. 已落地优化

### 2.1 零值门控（已有）

在 WS/IS/OS 的 MAC 路径中，当任一操作数为 0 时，直接保留当前部分和，不触发无意义乘加路径切换。

效果：

- 在稀疏输入下减少组合逻辑翻转
- 与功能正确性解耦（结果保持一致）

### 2.2 valid 门控寄存器写入（本次新增）

在流水线 token 无效周期（`valid=0`）：

- 仅更新 `valid` 与必要控制状态
- `data/tag/weight` 寄存器保持不变（不重复写入）

这样可以降低空拍传播导致的寄存器翻转活动，特别适合稀疏或间歇输入。

## 3. 关键代码位置

- WS：`ws/src/standard_ws_array_4x4.v`
  - 在主推进循环中，对 `data_pipe/row_tag_pipe/psum_pipe` 增加 `current_valid` 门控写入。
- IS：`is/src/standard_is_array_4x4.v`
  - 在主推进循环中，对 `weight_pipe/col_tag_pipe/psum_pipe` 增加 `current_valid` 门控写入。
- OS：`os/src/standard_os_array_4x4.v`
  - 对 `a_pipe/b_pipe` 增加各自 `current_a_valid/current_b_valid` 门控写入。

以上改动都属于“低翻转实现优化”，不改变数据流语义。

## 5. 如何读低功耗统计

在 `.txt` 回归中，每个用例与最终汇总都会输出：

- `active_mac`：真正执行的 MAC 次数
- `zero_gated`：被零值门控旁路次数
- `skip_ratio / avg_skip_pct`：跳过比例

它们用于评估当前数据集的稀疏性收益；不是电源签核值，但可作为前期优化指标。

## 6. 后续可选优化方向

- 增加可配置边界 FIFO/延迟线（用于不同时序约束实验）
- 为 `busy/done` 增加更细粒度活动跟踪（减少保守 busy 保持时间）
- 在综合脚本中增加功耗导向策略并固定约束模板
